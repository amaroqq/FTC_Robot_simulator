How the Simulation Works

This workspace is designed to test standard FTC robotics logic completely inside your browser. Because web browsers are single-threaded, a typical Java infinite loop like while (opModeIsActive()) would lock up the page. To avoid this, our system compiles your Java code into a JavaScript Generator Function.

This allows the simulation to yield control back to the computer's rendering engine every frame. Consequently, the Three.js virtual viewport and Rapier.js physical engines can update at 60 FPS while your robot program executes in parallel.

Hardware Mapping & Motor Directions

Just like programming a real FTC robot, you must connect your code to physical hardware ports using the hardwareMap. Furthermore, because left and right motors are mounted mirrored to each other on the chassis, you must set the right motors to REVERSE to ensure positive power pushes the robot forward.

DcMotor frontLeft = hardwareMap.get(DcMotor.class, "frontLeft");
DcMotor frontRight = hardwareMap.get(DcMotor.class, "frontRight");

// Reverse right motors
frontRight.setDirection(DcMotor.Direction.REVERSE);

Mecanum Chassis Coding & Kinematics

The simulated robot uses Mecanum Wheels. Because the rollers are aligned at a $45^\circ$ angle on the wheels, rotating the motors in specific patterns cancels or combines structural friction vectors. This lets the robot move sideways (strafe) and diagonally without changing its forward orientation.

To compute the motor power levels required for omnidirectional movement based on driving, strafing, and turning control values, we apply the following kinematic equations:

\begin{align*} v_{\text{frontLeft}} &= \text{drive} + \text{strafe} + \text{turn} \\ v_{\text{frontRight}} &= \text{drive} - \text{strafe} - \text{turn} \\ v_{\text{backLeft}} &= \text{drive} - \text{strafe} + \text{turn} \\ v_{\text{backRight}} &= \text{drive} + \text{strafe} - \text{turn} \end{align*}

Because these combinations can result in calculated motor powers exceeding 1.0, it is best practice to scale the results dynamically in your TeleOp code:

double max = Math.max(Math.max(Math.abs(fl), Math.abs(fr)), Math.max(Math.abs(bl), Math.abs(br))); if (max > 1.0) { fl /= max; fr /= max; bl /= max; br /= max; }
